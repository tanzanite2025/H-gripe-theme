## 3. 状态与边界

### 3.1 上下文事实源仍需补齐（P1，需后端契约）

上下文使用弹窗/抽屉是有意的跨端交互，不是缺陷。问题在于数据事实源覆盖不足，不能通过前端换成三栏布局解决。

当前与目标的边界如下：

| 事实 | 当前可用 | 缺口和限制 |
| --- | --- | --- |
| 时区/当地时间 | `contact.timezone`、来源、当地时间和昼夜阶段 | 已展示客服与客户当前时差；通知设置支持个人本地时间夜间免打扰，不改变未读状态。 |
| 收货地址 | 已接入基础投影 | 默认取最近订单地址，仅返回收件人、地址行、城市/州、邮编、国家和是否留有电话；完整电话、邮箱不返回。 |
| GeoIP | 只有粗略地区/来源信号 | 不能把粗略地区当作原始 IP，也不能直接下高风险结论；需独立风控事实源。 |
| 浏览足迹 | `product_id`、浏览次数、最后访问时间、商品名称、SKU、缩略图、币种和目录价 | 商品已删除或读模型失败时保留浏览事实，但对应商品字段为空；不把商品补全失败误报成整块不可用。 |
| 购物车 | 商品名、图片、SKU/变体、数量、单价、行小计和购物车币种 | 已明确使用购物车项目保存的价格快照并按币种展示；购物车区块仍不提供库存锁定快照，也不把目录当前价冒充成交价。 |
| 订单 | 订单号、状态、支付/物流状态、币种和价格拆分已接入 | 履约返回承运商、服务线路、追踪号、同步状态；商品返回订单快照名称/SKU/缩略图/数量/价格，库存快照缺失时明确标记。 |
| 售后/RMA | 已接入完整客服摘要 | 返回售后类型、状态、原因、商品摘要、当前处理人、处理结果、退款摘要和保修专属字段；退款与保修事实源分别有独立状态。 |
| Stripe/PayPal 争议 | 已接入摘要投影 | 返回渠道、订单、状态、原因、金额、币种、证据截止/提交时间；不返回原始 payload、charge、payment intent 或 provider payment ID。 |

要求：

- 把“当前接口已有字段”和“计划新增字段”分开，不得在前端文档中把计划字段伪装成已存在接口。
- 每个区块支持 `available / unavailable / permission_denied / error` 等明确状态；“无数据”不能统一显示成“未采集”。
- 地址、支付争议和风控信号必须经过后端授权、审计和脱敏设计；原始 IP、完整支付信息、访客哈希不得进入普通客服上下文。
- 上下文弹窗打开时刷新数据；刷新失败保留上次数据并显示时间戳和错误状态，不能静默覆盖为“未采集”。
- 当前 `fetchContext` 请求失败会保留最近一次成功快照，并单独暴露 `contextError`/刷新时间；区块级事实源错误由后端返回 `status: error`，不会把整份上下文静默标成“未采集”。

### 3.2 时区显示语义和“未采集时区”排查规则

“未采集时区”只允许表示 `contact.timezone` 缺失、格式非法或来源未通过校验，不得因为地区为空、GeoIP 不可用或请求刷新失败而误显示。

当前后端事实源顺序是：先按会话的 `visitor_session_hash` 查访客档案，档案没有有效时区时再按登录用户 ID 查访客档案；匿名会话没有有效的访客档案或浏览器没有上报 IANA 时区时，仍然会是未采集。成功写入的来源当前为 `visitor_profile`，不能把“访客地区”或 GeoIP 信号当成时区已采集。由于历史导入或并发首次采集可能产生重复 visitor profile，查询按 `updated_at DESC, id DESC` 优先取最新记录，避免旧的空时区记录遮蔽新值。

现有截图中同时出现“匿名访客已建立 visitor profile”和 `timezone_source=not_captured`。这两个状态并不矛盾：访客档案存在不代表档案已经保存有效时区；应继续追踪浏览器上报和档案写入链路，而不是在前端用地区值替代时区。

约束：

- 有效时区时同时显示 IANA 时区、当地时间、日期、昼夜阶段和 `timezone_source`。
- 无有效时区时显示“未采集时区”，并明确显示原因（无数据、权限限制或刷新失败）。
- 不得仅凭国家/地区名称硬推时区并标记为已采集；推断值必须有独立来源和置信度。
- 打开上下文弹窗必须重新请求上下文；请求中的旧值可继续展示，但应标记为刷新中。
- 客服与客户时差按当前日期的实际 IANA offset（包含夏令时）计算并展示；不能用固定地区差值。
- 夜间免打扰已作为客服个人通知偏好实现：按客服浏览器本地时间静默提示音和桌面通知，不改变会话未读状态；尚未实现管理员强制覆盖或按客户时区统一静默。

排查“明明上报了时区仍显示未采集”时，按以下顺序核对：浏览器请求是否携带 IANA 时区、访客档案是否按当前会话 hash 写入、上下文 API 返回的 `contact.timezone` 是否为空、前端是否因请求失败把上下文清空。不能只看地区信号或数据库中另一条用户档案记录就判定 UI 有问题。

### 3.3 通知策略的产品边界（P2）

提示音和桌面通知的基础设置已经落地：开关、音量、测试入口、授权状态和本地偏好均由工作台提供。通知只针对客户新消息，并按 `event_id` 去重；浏览器不支持通知或用户拒绝授权时仍保留站内未读状态。当前会话在前台聚焦时默认只静默桌面通知，客服仍可在通知设置中关闭该策略；跨标签页优先使用 Web Locks 原子认领事件，不支持时使用 BroadcastChannel 的确定性短等待兜底。

当前个人通知策略已完成。管理员级默认值覆盖属于独立产品决策：在没有配置模型、权限、审计和接口契约前不实现强制覆盖。夜间策略只按客服浏览器本地时间和个人偏好执行，不按客户时区统一静默，避免把客户当地夜间误当成客服值班免打扰。浏览器权限已拒绝时，应用不能再次触发权限弹窗，用户需在浏览器站点设置中恢复权限。

## 4. 生命周期与删除边界

会话列表治理已经落地，本文不再把“无法删除聊天”描述为未实现功能。普通客服的“删除”需求应解释为“从我的收件箱归档”，而不是物理删除。

当前交互：

- 默认 `Inbox` 只显示当前客服未归档的 `open` / `in_progress` 会话。
- `Closed`、`Archived`、`All` 是独立视图，搜索和分页由服务端执行。
- 行菜单提供“关闭并归档”“仅归档”“恢复到收件箱”“重新打开”；支持批量归档。
- 归档/关闭/恢复/重新打开使用服务端命令和可撤销 Toast，不能只修改前端数组。
- 客户新消息会重新打开必要的全局状态并清除当前受理人的归档标记。
- 不提供常规硬删除按钮。生命周期文档 Phase 3 已实现管理员资格检查、依赖检查、软删除、恢复窗口、审计清理命令和可选定时 purge worker；普通客服仍只能归档/关闭。worker 默认关闭；环境变量只提供首次初始化默认值，运行中的启用状态、保留期限、恢复窗口、间隔和批量上限由客服保留运维页面配置，并持久化在客服对话域策略表中。

任何新增列表、详情或实时写路径都必须链接并遵守生命周期事实源，不能重新引入“关闭即删除”“归档即全局隐藏”或“访客档案归档等于会话归档”等语义。

## 5. 实施顺序

### Phase A：工作台设置状态

已完成：提示音开关、音量/测试入口、桌面通知开关、授权状态和首次授权入口。默认提示音音量为 12%，偏好按浏览器本地保存。

已完成：聚焦会话静默策略（默认只静默桌面通知）、跨标签页通知去重、个人夜间免打扰，以及新会话 `conversation.created` 的事务型 durable outbox 事件。管理员默认值覆盖、购物车库存锁定快照和 `conversation.context.updated` 不属于当前版本的已承诺实现：前者等待产品决策，后两者分别等待真实事实源和上下文写入命令。系统不按客户时区统一静默。

### Phase B：补齐上下文事实源

1. 与订单、地址、浏览、购物车、售后和支付风控负责人确认事实源、权限、字段口径和刷新 SLA。
2. 已完成：订单履约、价格口径、购物车币种/价格快照、售后处理人/退款明细/保修字段和权限审计；每个卡片保留可用、无数据、无权限和错误状态。库存锁定快照当前明确为 `not_captured`，不能用当前库存冒充锁定事实；若未来库存系统提供锁定事实，再单独设计接入。
3. 已完成时区来源、刷新状态和客服时差展示；当前已补充重复 visitor profile 取最新记录的专项回归测试。个人夜间免打扰已完成并覆盖跨午夜、边界时间和非法配置测试；客户时区不参与客服通知静默。

### Phase C：生命周期保留操作

已完成：按 [`customer-service-conversation-lifecycle-and-inbox-architecture.md`](./customer-service-conversation-lifecycle-and-inbox-architecture.md) 接入管理员保留资格检查、依赖检查、软删除、可配置恢复窗口、脱敏审计的受控清理命令，以及默认关闭的定时 purge worker、客服对话域运行时策略配置和 Prometheus 指标；不得在客服列表中加入硬删除按钮。

## 6. 验收矩阵

| 场景 | 必须结果 |
| --- | --- |
| 点击图片 | 原地打开 Lightbox，可切图、缩放、旋转、Esc 关闭，不打开新标签页。 |
| 输入法合成中按 Enter | 不发送，不破坏正在组合的中文字符。 |
| 普通 Enter / Shift+Enter | Enter 发送；Shift+Enter 换行。 |
| 粘贴截图 | 图片上传并发送；粘贴普通文本不被吞掉。 |
| A/B 会话切换 | 每个会话草稿独立保留，发送后只清当前草稿。 |
| 打开长会话 | 直接定位最新消息；上翻后新消息不抢焦；可点击入口回到底部。 |
| 有有效时区 | 显示时区、当地时间、日期、昼夜阶段、来源和相对客服浏览器的当前时差。 |
| 无有效时区 | 显示“未采集时区”及原因，不伪造时区；刷新失败不覆盖已有值。 |
| 上下文无地址/售后数据 | 显示对应区块的“尚未接入/无权限/无数据”状态，不声称系统已有该事实。 |
| 归档会话 | 仅从当前客服 Inbox 消失，消息仍保留，可从 Archived 恢复。 |
| 客户回复已关闭会话 | 按生命周期事实源重新打开、取消归档并产生实时失效。 |
| 普通客服点击删除 | 只提供归档/关闭操作，不发生硬删除。 |
| 定时保留清理 | 仅管理员保留策略和已过恢复窗口的软删除会话进入 worker；依赖 hold 或清理错误会跳过并保留审计/指标。 |
| 聚焦会话收到新消息 | 默认不弹桌面通知，站内未读和提示音策略保持独立；关闭聚焦静默后恢复桌面通知。 |
| 多个客服标签页收到同一事件 | 同一 `event_id` 只允许一个标签页产生桌面通知；不支持 Web Locks 时使用 BroadcastChannel 兜底，失败不影响站内消息刷新。 |
