# Schwalbe 车圈内宽匹配设计

> **状态：已进入实施，数据契约和职责边界保持本文定义。**
>
> 本文只定义用户流程、数据语义、职责边界和实施顺序。它不改变选型页、接口、数据库或筛选 URL。

## 1. 目标

在 Schwalbe 外胎选型页增加一个用户能直接理解的入口：用户选择轮径和 BSD，输入自己的车圈内宽，页面返回落在官方胎宽—车圈内宽可能组合范围内的外胎候选。

这个入口解决的是“我的车圈能从哪些胎宽开始找”的问题。它不把目录字段 `BSD`、`ETRTO` 或 `Version` 暴露成用户必须理解的第一步。

## 2. 先确定匹配语义

### 2.1 第一阶段只做官方范围匹配

迁移 362 的规则描述的是胎宽和车圈内宽的**可能组合范围**。一个目录候选命中规则的条件是：

```text
规则胎宽最小值 <= 候选 ETRTO 胎宽 <= 规则胎宽最大值
并且
规则内宽最小值 <= 用户输入内宽 <= 规则内宽最大值
```

结果文案使用以下语义：

- `官方可能组合范围内`
- `暂无官方范围覆盖`
- `缺少可解析的 ETRTO，无法判断`

第一阶段不输出 0–100 分、黄金内宽、最佳截面、兼容认证或安全结论。预览 HTML 中的 `optimalRimWidthMm`、`fitScore`、`hooklessApproved` 和 `rawTires` 都属于历史 mock 交互，不能成为生产字段或算法来源。

### 2.2 车轮尺寸仍然是必要条件

车圈内宽不能替代轮径和 BSD。相同的内宽可以出现在不同轮组上，因此匹配入口应优先组合：

```text
轮径 + BSD + 车圈内宽
```

现有 `wheel_size` 复合键继续使用，例如 `28-622`、`29-622`、`26-559` 和 `26-590` 必须保持互相独立。未选择轮径时可以保留全库浏览，但“按我的车圈匹配”状态应提示用户补充轮径和 BSD，结果也要按复合尺寸分组或明确显示尺寸。

### 2.3 不能从内宽推导的结论

以下结论需要额外的逐型号事实、轮圈厂商要求、车架间隙和压力规则，不能由当前规则表推导：

- 某个具体型号的完整轮圈兼容认证；
- Hookless、TLE/TLR 或胎圈系统认证；
- 车架、前叉和挡泥板间隙；
- 最大安全胎压；
- “黄金搭配”或跨型号性能排名。

## 3. 建议的用户流程

### 3.1 页面入口

轮径 + BSD、车圈内宽和目录属性都在同一个筛选弹窗内编辑。页面外只保留当前结果摘要和筛选入口，避免顶部快捷控件与弹窗尺寸条件形成两套状态。

弹窗的尺寸手风琴包含：

1. 轮径 + BSD 多选，复用现有尺寸选项；
2. 可选的车圈内宽数字输入，单位为 `mm`；
3. 一句说明：这是官方可能组合范围，不替代轮圈厂商和车架检查；
4. 清除车圈匹配操作。

内宽为空时，轮径 + BSD 是普通的多选尺寸筛选。内宽非空时必须恰好选择一个轮径 + BSD，弹窗提交按钮在输入无效或尺寸数量不正确时禁用。移动端继续使用抽屉底部的一次性“查看结果”提交，所有尺寸和属性条件都在同一份草稿中维护。

### 3.2 结果表达

结果摘要可以显示：

```text
28"（BSD 622） · 车圈内宽 23 mm · 官方可能组合范围内 146 条
```

每张卡片显示：

- 轮径 + BSD；
- ETRTO 和名义胎宽；
- `官方可能组合范围内` 状态；
- 规则覆盖的内宽区间，例如 `16–25 mm`；
- 现有重量排序和商品存在状态。

不显示没有来源支撑的“黄金点”或模拟分数。用户需要看具体型号事实时，仍通过现有卡片详情查看目录字段。

## 4. 数据和接口契约建议

### 4.1 URL 状态

新增单值查询参数：

```text
inner_rim_width_mm=23
```

建议规则：

- 没有该参数时，页面行为保持当前全目录行为；
- 数值必须为正的有限数，URL 使用规范化后的十进制表示；
- 允许测量值使用小数，但不能把输入强行吸附到规则端点；
- 清除内宽时删除该参数并回到未匹配上下文；
- 内宽、轮径、BSD 或其它筛选变化都回到第一页；
- 直链、刷新、前进后退和 SSR 都恢复相同匹配上下文。

参数名称采用 `inner_rim_width_mm`，避免和车圈外宽、胎宽或胎压计算器中的展示字段混淆。

### 4.2 Selector API

`GET /products/schwalbe-tire-catalog/selector` 接收 `inner_rim_width_mm`，在服务端完成匹配后再排序和分页。

客户端不能只对当前 20 条结果做过滤，否则 `total`、`total_pages`、SSR 首屏和分页链接都会失真。

响应可增加一个轻量的匹配上下文，用于页面说明和来源展示：

```json
{
  "rim_width_context": {
    "inner_rim_width_mm": 23,
    "guidance_status": "covered",
    "source_basis": "ETRTO Standard 2024; Schwalbe possible combinations guidance",
    "source_version": "05/2024",
    "source_checked_at": "2026-09-28"
  }
}
```

`source_url` 是否直接暴露给 storefront 继续遵守现有公开数据边界；页面只需显示来源名称、版本和核验日期即可。

### 4.3 服务端过滤顺序

选型服务应保持以下顺序：

1. 读取文本搜索命中集；
2. 派生严格 ETRTO 胎宽和轮径 + BSD；
3. 应用内宽可能组合条件；
4. 应用现有型号、胎宽、尺寸、结构和属性筛选；
5. 按重量排序；
6. 计算总数并分页。

缺少或无法解析 ETRTO 胎宽的候选，在用户启用内宽匹配时不能被当成命中。没有启用内宽匹配时，现有目录行为保持不变。

### 5.1 当前职责是否足够

当前结构已经覆盖功能接入层：后端 selector query、服务端规则过滤、前端 URL/query/composable、筛选弹窗草稿、匹配上下文摘要和分页回归测试各自保持原有职责。后续如果增加新的轮圈厂商规则，仍应新增可复用的后端纯规则判断层，避免把相同算法分别写在 handler、selector service 和 repository 中。前端判断函数只能用于契约测试和非分页消费者，不能成为 storefront 结果的权威过滤层。

## 6. 异常和边界状态

- 输入为空：显示全目录，不保留匹配上下文；
- 输入格式错误：不发请求，保留原结果并提示有效单位；
- 内宽超出规则覆盖：显示“暂无官方范围覆盖”，不把所有结果标为兼容；
- ETRTO 缺失或格式异常：候选不能命中内宽规则；
- 规则存储或 selector 服务不可用：匹配请求显示明确错误，不静默退回全目录；
- 规则表为空：结果状态为“暂无官方范围覆盖”，同时记录监控或日志；
- 与轮径 + BSD 组合无交集：显示无结果，并保留当前 URL 以便分享和复查。

## 7. 测试和验收顺序

按以下顺序验收：

1. 规则纯函数：端点包含、区间外排除、缺少 ETRTO 排除；
2. 后端 selector：内宽过滤发生在分页前，`total` 和 `total_pages` 正确；
3. API：内宽与 `wheel_size`、胎宽范围、搜索和重量排序组合稳定；
4. 前端 URL：输入、清除、直链、前进后退和页码重置；
5. SSR：首屏摘要与结果和客户端一致；
6. 移动端：输入、提交、清除和结果摘要不产生横向溢出；
7. 文案：所有结果状态都使用“可能组合”语义，不出现认证或黄金匹配承诺。

## 8. 暂不处理的扩展

- 逐型号 Hookless/TLE/TLR 认证；
- 轮圈制造商白名单或型号数据库；
- 车架和前叉间隙计算；
- 依据每个型号的官方最佳内宽做匹配分数；
- 从内宽自动推导胎压上限；
- 将内宽规则写入 19 项 Schwalbe 销售商品模板字段。

这些功能需要单独来源、数据模型和验收标准，不能和第一阶段的可能组合筛选混在一起。

## 8.1 与目录筛选弹窗的冲突处理

车圈内宽匹配和目录筛选弹窗共用一份草稿，不再把页面外控件和弹窗条件隐式叠加：

- 轮径 + BSD 与内宽位于同一个尺寸手风琴；内宽为空时支持多个轮径 + BSD，内宽非空时必须恰好保留一个尺寸；
- 弹窗提交明确胎宽范围时，切换到胎宽尺寸模式并清除内宽匹配，避免用户看不到的双重尺寸 AND 条件；
- 弹窗中的承重、胎体、胎圈、密封、E-Bike、颜色和胶料仍可作为车圈匹配后的二次筛选；
- “清除筛选”会清除轮径、BSD、内宽和其它目录条件；车圈匹配结果为空时的恢复操作可以清除这些二次条件；
- 胎宽手风琴提供独立的“清除胎宽”操作，尺寸草稿在点击“查看结果”前不会改变 URL 或目录结果；
- 内宽输入为空时不会发送 `inner_rim_width_mm`；输入有效且只有一个轮径 + BSD 时才提交内宽匹配，保证 UI 状态和服务端条件一致。

这样 URL 仍然是唯一的已提交状态来源，弹窗草稿在点击“查看结果”前不会影响结果；用户的普通属性筛选不会被静默丢弃，只有互斥的两种尺寸模式会明确切换。

## 9. 已固定的实现选择

以下选择已经作为当前实现的契约：

1. **输入精度和范围**：当前允许 0.1 mm 的正数测量值；规则元数据决定结果覆盖范围，不复制预览中的固定 `13–40 mm`。
2. **轮径是否强制**：只有同时选择轮径 + BSD 后才进入“按车圈匹配”上下文；未选择时继续支持全库浏览。内宽输入存在但尺寸不是一个时，弹窗禁止提交。
3. **未命中候选的展示**：默认只展示规则命中的候选，并在摘要中说明规则覆盖情况；不把未命中项混在结果中制造“兼容/不兼容”误读。
4. **来源上下文位置**：建议由 selector 响应返回版本和核验日期，页面统一展示；不要让页面为每次查询单独请求规则并自行决定分页结果。
