## 二、 第一支柱：前后端解耦与核心算法安全隔离

### 1. 前后端职责硬性边界
- **前端（Presentation Layer）职责**：
  - 仅负责收集用户输入参数（滑块拖动、下拉选择、车手参数）；
  - 仅负责接收后端返回的标准力学结果并做动态图表与动效渲染；
  - **严禁在前端编写任何核心物理推导矩阵、材料微观位错演变拟合方程或非线性优化求解器**。
- **后端（Domain Engine）职责**：
  - 承担专有算法库（Proprietary Algorithms）；
  - 维护材料物性常数数据库（如奥氏体不锈钢晶格常数、CX-Ray 应力-应变曲线、车圈孔座撕裂极限）；
  - 输出规范化的结构化力学结果。

### 2. 接口反爬与防黑盒逆向工程
公开的计算接口必须部署以下防线，防止竞对通过脚本批量穷举输入输出以拟合回归方程：
1. **严格的分布式速率限制（Rate Limiting）**：
   - 匿名访客：基于 IP + 浏览器指纹，限制单个计算接口单分钟请求不超过 20 次；
   - 突发请求拦截：启用令牌桶算法，瞬时突发上限限制在 5 次；
2. **非连续数值微扰动与混淆**：
   - 对于非生产下料的展示性效率曲线（如有效力矩传动效率 $H$），仅对外输出物理有效位（如保留至小数点后 1 位），截断微观尾数，增加逆向推导的数学残差难度；
3. **WAF 异常行为拦截**：
   - 监测均匀线性递增（如以 0.1 为步长连续遍历 1000 次）的参数调用，直接判定为爬虫并触发 429 或 Cloudflare 验证码挑战。

## 三、 第二支柱：搜索引擎与 AI 爬虫全景可达性工程

为了确保 Google 核心搜索算法与主流 AI 爬虫（GPTBot, PerplexityBot, ClaudeBot, Google-Extended）能完整抓取、理解并高频引用页面的权威数据，必须严格遵循以下规范：

### 1. 服务端渲染（SSR）首屏直出标准
- **禁用客户端纯 JS 挂载核心内容**：
  - 页面的基础力学定义、公式、出厂指标（如 1200N / 1620N / 1850N）、下料规格矩阵表**必须在 Nuxt 服务端渲染（SSR）阶段直接生成于 HTML 源码中**；
  - 爬虫抓取到的第一份 HTML 必须包含基准配置（例如：50mm 圈高、12 孔、等长硬约束）的完整解，爬虫无需执行任何 JavaScript 即可提取完整技术事实。

### 2. 规范化结构化数据（Schema.org JSON-LD）
每个算法页面必须在 `<head>` 中动态注入符合学术与工程规范的 JSON-LD 标记：
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "TechArticle",
  "headline": "轮组应力释放与不锈钢微观位错力学工程白皮书",
  "version": "V1.0-ENGINEERING",
  "proficiencyLevel": "Expert",
  "articleBody": "详细阐述奥氏体 AISI 302/304 不锈钢冷拔丝在 135% 预应变过向态饱和下的 Lomer-Cottrell 位错壁卡死机制...",
  "author": {
    "@type": "Organization",
    "name": "Guangenwang Engineering Lab"
  },
  "inLanguage": "zh-CN",
  "hasPart": [
    {
      "@type": "Dataset",
      "name": "碳辐条轮组参数化动态下料公差矩阵",
      "description": "涵盖 35mm-60mm 圈高的左右同模等长求解数据"
    }
  ]
}
</script>
```

### 3. 多语言与 Sitemap 自动收录链条
- 页面路由必须自动登记进 `StorefrontRouteCatalogService`，确保 `/api/v1/storefront/sitemap-routes` 及 Nuxt 动态站点地图能够即时收录；
- 多语言版本必须配置严格对称的 `<link rel="alternate" hreflang="..." />` 标签，避免被搜索引擎判定为内容农场。

## 四、 第三支柱：数值稳定性、浮点精度与 Fail Loudly 物理边界校验

算法页面不仅是展示，更是定制下单的前哨站。计算引擎必须具备工业级的数值稳定性：

### 1. 物理安全窗口硬断言（Fail Loudly 原则）
禁止任何静默容错（如 `|| 0` 或 `try-catch { return 1200 }`），所有输入必须经过严格的物理边界守卫：
```go
// 严禁使用任何隐式兜底，必须大声报错拦截
if input.SpokeAngleDegrees < 0 || input.SpokeAngleDegrees > 90 {
    return nil, fmt.Errorf("[CRITICAL] Spoke angle %.2f° violates physical half-plane boundary [0, 90]", input.SpokeAngleDegrees)
}
if input.RiderWeightKg <= 0 || input.RiderWeightKg > 200 {
    return nil, fmt.Errorf("[CRITICAL] Rider weight %.2f kg out of design load envelope (0, 200]", input.RiderWeightKg)
}
if math.IsNaN(result.TensionRatio) || math.IsInf(result.TensionRatio, 0) {
    return nil, fmt.Errorf("[CRITICAL] Tension ratio calculation diverged into non-finite value")
}
```

### 2. 浮点精度噪声消除与工程舍入
- **长度与下料公差**：辐条下料尺寸一律在后端精确四舍五入到 **$0.01\text{ mm}$**，并在生成切割规格时对齐到车间标准的 **$1\text{ mm}$** 整数规格；
- **张力比与力矩臂**：百分比一律保留至小数点后 2 位（如 `115.25%`），禁止在 API 中直接暴露带有浮点噪声的 IEEE-754 原始尾数（如 `115.25000000000001%`）。

## 五、 第四支柱：前端交互呈现与矢量图形规范

对于复杂的力学矢量图、剖面受力图与几何三角投影，前端呈现必须遵循以下准则：

### 1. 渲染选型标准：严禁使用裸 Canvas 作为主要表达
| 技术方案 | 对 SEO / AI 的可读性 | 交互性能 | 矢量保真度 | 适用场景 |
| :--- | :---: | :---: | :---: | :--- |
| **内联 SVG (`<svg>`)** | **极高**（所有 `<text>` 标签可被全文抓取） | 极高（百级节点内无压力） | **无限放大清晰**，工业图纸质感 | **力矩臂仿真、花鼓开孔剖面、位错图（推荐标准）** |
| **纯 HTML5 Canvas** | **零**（爬虫只能识别为黑盒或空白） | 适合万级粒子或高频渲染 | 缩放需重绘，易模糊 | 仅限复杂物理碰撞游戏或大型流体力学模拟 |

- **强制要求**：图中所有的力学符号（如 $r_{\text{eff}}$、$\theta$、PCD、法兰半径）、应力数值、状态切换说明，**必须作为 DOM 或 SVG `<text>` 节点存在**，严禁将文字直接烘焙进位图（PNG/JPG）中展示。

### 2. 符合 ERP UDS 1.0 工业级设计美学
- 遵循工业图纸质感：采用虚线边框 (`border-dashed`)、黑白灰高对比色谱、紧凑等宽字体（`font-mono`）；
- 核心指标卡使用大圆角物理容器（`rounded-[24px]`），配合极细分割线，杜绝浮夸的花哨装饰，突显硬核工业标准。

## 六、 第五支柱：从动态计算到车间质检的不可篡改证据链闭环

这是区别于普通“营销吹嘘网站”与“真正硬核制造品牌”的最关键防线：

```
[前台交互看板选型] 
       │ (用户选择：50mm圈高 / 1:1二叉 / 锁定等长)
       ▼
[生成结账与订单快照 (OrderEvidenceSnapshot)]
       │ (将 PCD_L=49.2mm, L_R=260.75mm, 目标张力 1200N 作为不可篡改 JSON 固化入订单)
       ▼
[车间排产与物理下料 (OrderProductionService)]
       │ (严格依照快照规格下料与编轮，消除技师人为口头传达误差)
       ▼
[出厂张力实测质检 (SpokeQCTension Evidence)]
       │ (张力计实测 24 根辐条数值，校验张力衰减率 < 0.8%)
       ▼
[履约证据归档与放行 (CheckFulfillmentReadiness)]
       │ (必须具备真实张力质检报告，严防虚假发货)
       ▼
[包裹派送与争议抗辩 (Dispute Evidence Package)]
       │ (若发生客户争议，直接调用初始计算快照与质检证据，抗辩胜率 100%)
```

1. **计算结果必须具备快照不可篡改性（Immutability）**：
   用户通过选型看板加入购物车或下单时，前端计算出的最终下料参数和张力要求必须打包为 `selected_engineering_specification`，存入 `order_items` 表。订单生成后，**禁止任何人二次修改该力学规格**；
2. **前后端证据闭环**：
   车间发货时，必须上传该批次对应的《出厂辐条张力实测表》，系统自动比对实测数值与白皮书中声明的“1200N $\pm 5\%$ 窗口”。**只有实测数据落在理论安全窗口内，发货门禁才予以放行**，真正做到“算什么、编什么、检什么、发什么”。

## 七、 研发核对检查清单

在任何新的技术算法或计算器页面上线前，开发与质量团队必须逐项核对本清单：

- [ ] **1. 算法隔离**：核心力学公式、微观蠕变方程是否已全部迁移至 Go 后端，前端无暴露核心常数？
- [ ] **2. 接口频控**：计算 API 是否已配置基于 Redis 令牌桶的 IP 速率限制，防止爬虫穷举逆向？
- [ ] **3. SSR 首屏直出**：在禁用浏览器 JavaScript 的情况下刷新页面，能否完整看到默认配置的力学表格、公式与核心参数？
- [ ] **4. 矢量文字**：仿真图表是否采用内联 SVG，图中标注是否均为可选中的 `<text>` 节点而非像素图片？
- [ ] **5. 结构化数据**：页面的 `<head>` 中是否已正确输出 `TechArticle` / `Dataset` 的 JSON-LD 标签？
- [ ] **6. 物理边界守卫**：输入非法角度、超标载荷、异常字符时，后端是否遵循 Fail Loudly 原则立刻阻断报错，无任何 NaN 扩散？
- [ ] **7. 精度规范**：所有输出给前端的浮点数是否已完成四舍五入与公差截断，杜绝 IEEE-754 精度噪声？
- [ ] **8. 订单快照集成**：选型计算产生的最终定制参数，是否能在结账时完整被 `OrderEvidenceSnapshot` 固化存证？
