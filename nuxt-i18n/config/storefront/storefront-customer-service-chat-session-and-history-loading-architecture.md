# 客服聊天会话与历史消息加载架构

本文记录客服聊天从打开、折叠、重新展开、关闭到再次打开的状态约定，以及本地草稿、消息缓存、服务端历史和实时同步的分步改进。后端会话和消息是最终数据来源；浏览器缓存用于快速呈现和短时离线恢复，不应成为唯一副本。

## 当前行为与已确认缺口

- 抽屉手柄执行折叠，遮罩、关闭按钮和 Escape 执行关闭。折叠时聊天组件及实时连接继续挂载，聊天主体进入 `inert` 和 `aria-hidden`；Teleport 到 `body` 的次级抽屉、登录弹窗和提示会一并收起，避免折叠后仍覆盖页面。
- 已发送消息写入按访客/会员身份、会话和客服隔离的五天本地缓存；重新打开时先呈现本地副本，再从服务端同步。
- 会话 ID 持久化在按会员 ID 或本浏览器访客身份分区的版本化记录中；访客/会员切换会重置内存房间并恢复各自会话。服务端返回权限失效时清除当前身份对应的会话 ID。
- 草稿单独保存为版本化小记录，输入时立即写入，保留五天；空草稿会移除记录。旧真实会话缓存会在服务端恢复当前身份的会话 ID 后迁入新作用域。
- 旧版本的 `pending` 缓存没有访客/会员归属信息，因此不会自动迁入当前账号，以免把同一浏览器其他身份的离线消息或草稿混入会话。
- 历史接口保留旧 `limit`/`offset` 分页，并新增基于 `(created_at, id)` 的游标分页：`latest=true` 取最新页，`before_created_at`/`before_id` 向前读旧记录，`after_created_at`/`after_id` 补取新记录。响应提供方向性 `has_older`/`has_newer` 和首尾游标；精确游标 ID 以十进制字符串提供，避免 64 位 ID 在 JavaScript 数字中失真，原数值 `id` 字段继续兼容。
- 客户端首屏先恢复本地缓存，再请求服务端最新一页；顶部可继续加载旧页，按消息 ID 合并并保留已加载页，加载后恢复原滚动锚点。旧游标从缓存中最早的已确认服务器消息继续，因此重开会话时不会反复拉取本地已有的历史页。实时事件、重连和浏览器回到前台从最新服务端游标后增量读取；尚无服务端游标时改读最新页，避免空会话漏掉已经落库但发送响应丢失的消息。相同会话的并发同步合并，读取期间新到事件会再触发一次增量校准；历史记录按服务端消息 ID 与 `client_message_id` 合并，未匹配的本地失败消息仍保留并可重试。
- 消息表通过 `(ticket_id, created_at, id)` 复合索引支持稳定游标查询；现有 offset 客户端仍兼容，不会被切换到新的排序语义。
- 消息发送为每条本地乐观消息保存稳定的 `client_message_id`；服务端按会话唯一约束该 ID，并比较规范化请求摘要。相同请求重试复用原消息，错误复用 ID 返回冲突，避免服务端已提交但响应丢失后产生双发。
- 已有可靠性基础：本地乐观消息、发送失败标记和重试、服务端消息按 ID 合并去重、WebSocket 重连和游标恢复。

## 目标状态约定

| 动作 | 组件与连接 | 对用户数据的要求 |
| --- | --- | --- |
| 打开 | 创建或恢复聊天会话 | 先呈现可用缓存，再与服务端校准 |
| 折叠 | 保留同一聊天组件、输入草稿、当前页签和实时连接 | 再展开时不重新初始化、不丢当前视图状态 |
| 展开 | 恢复同一组件的可见状态 | 仍能关闭、发送和切换客服 |
| 关闭 | 卸载组件并清理临时连接和计时器 | 服务端记录保留；本地草稿及待确认消息按持久化策略保留 |
| 再次打开 | 恢复稳定的会话身份，先缓存后服务端 | 不创建重复会话，不漏掉关闭期间的新消息 |

消息加载约定：初次进入聊天加载最新一页；用户向上查看时按稳定游标补充旧消息；实时事件与重连只做增量补齐。所有来源按服务端消息 ID 合并，未确认的本地发送消息继续保留并可重试。加载中、空会话、断网、权限失效和重试状态都必须有明确的界面状态。

## 交付步骤

1. **分离折叠和关闭（已完成）**：将折叠状态放到全局聊天控制器；手柄折叠和展开时保留当前组件；关闭按钮、遮罩和 Escape 仍能真正关闭；移动 Dock 点击已折叠的聊天时展开它。折叠时收起 Teleport 到 `body` 的次级浮层，确保面板区域外没有残留覆盖层。
2. **恢复会话身份与草稿（已完成）**：按访客/会员身份持久化会话 ID 和版本化草稿；恢复 ID 后先迁移对应真实会话的旧缓存，再读取本地消息和草稿；pending 缓存也按身份隔离。旧版归属不明的 pending 数据不自动复用。草稿及消息缓存五天过期，服务端不可用时保留本地副本。
3. **完整历史分页与实时补齐（实现已完成，端到端验收列入第 4 步）**：首屏加载最新页，向上用稳定复合游标读取旧记录；实时事件、重连与前台恢复用最新游标补齐新记录。服务端保留 offset 兼容，并为游标读取加复合索引；客户端合并去重已加载消息，分页后保持视口位置。
4. **生命周期回归验收（隔离浏览器 mock 已通过；真实后端网络验收待补）**：已覆盖折叠/展开、真正关闭后再打开、页面刷新、超过一页历史、发送中关闭、失败重试、无游标时回读最新页及移动端 Dock 安全区。访客/会员存储隔离由存储契约测试覆盖；真实访客与会员接口、分页与 WebSocket 并发、断网重连仍需后端可用时补验。
5. **失败发送的幂等恢复（服务层、公开接口和本地恢复契约已实现；浏览器模拟已验证幂等重试及无游标历史恢复；真实后端网络故障注入待补）**：每条乐观消息的客户端 ID 随本地消息持久化并在手动重试时复用；后端以会话范围唯一约束、请求摘要和事务内查重保证相同内容只落一条记录。重复 HTTP 请求返回原消息，不重复写 outbox 或触发自动回复；同键不同内容返回冲突。公开历史也返回客户端 ID，客户端能把增量同步取得的服务端记录与失败的乐观消息合并。迁移降级在存在幂等键时会明确拒绝，保留重试身份数据。
