# 税率数据快照与 Checkout 覆盖操作说明

## 目的

税率管理把三个职责分开：

1. **数据源配置**控制外部税率数据的采集频率。
2. **当前快照**保留某次采集到的地区、税率类别、版本、采集时间和内容哈希，供核对。
3. **地区覆盖核对与结算规则**显示后台销售市场、快照数据和 Checkout 实际读取的规则之间的差异。

外部快照不会自动创建、启用或覆盖 Checkout 规则。Checkout 只读 `tax_rates` 中已启用且匹配当前地址的明确规则。

## “正确税率”的定义

快照有一个税率数值，不等于该数值对本店当前交易正确。可用于收费的税额至少要符合销售方在目的地承担的纳税义务，并适用于交易发生时点、商品税务类别和具体地区。核实范围通常包括：

- 销售方是否在当地有纳税义务及所需登记；
- 商品适用的税务类别；
- 地址需要匹配到国家、州 / 省、地方辖区或邮编中的哪一级；
- 运费是否纳入计税、商品价格是含税还是未税，以及折扣如何影响计税基数；
- 规则的生效时间、失效时间、免税条件和可追溯依据。

因此，**正确的操作结果**是：税务适用范围已经核实，Checkout 使用一条明确覆盖该交易范围、带有可追溯依据并在交易日期有效的已发布规则；没有规则时阻止报价和下单。单独的免费税率接口无法替商家判断纳税义务、商品分类和各地适用范围。

## 当前实现的边界

- 当前固定接入 VATcomply 的 VAT 税率接口。现有数据覆盖欧盟成员国 VAT 参考税率，不是全球税务计算服务，也不判断某个商品应套用标准税率、优惠税率还是免税。
- 快照里的 `standard`、其他税率和商品类别税率都是来源数据。当前 Checkout 不读取快照，商品类别税率也没有映射到商品记录。
- 当前 Checkout 规则按国家、可选州 / 省和精确邮编匹配；有邮编时依次尝试精确邮编、州 / 省默认、国家默认。它对折扣后的商品净额应用一个匹配税率，不按商品税务类别分别计算，也不把运费计入这条税率的计税金额。
- 当前税率规则没有保存来源快照、生效区间或人工核验依据。地区覆盖 TAB 因此只能说明规则是否存在、数值是否与当前快照标准税率一致，不能声称已完成税务合规核验。
- 后台启用市场表示预期经营范围。市场列表本身不是 Checkout 的目的地准入规则；Checkout 是否能生成报价仍由物流结果和税率匹配等检查共同决定。

## 后台操作

### 1. 确认预期销售地区

先在“市场与本地化语种”中检查启用市场及其国家。税率管理的“地区覆盖核对”按这些国家汇总，同时列出已有 Checkout 规则但不在启用市场中的国家，便于发现遗漏或多余配置。

若没有启用且配置国家的市场，地区覆盖表会提示范围不完整。不要把空表解释为所有地区都已覆盖。

### 2. 采集并核对快照

在“数据源配置”中启用采集并设置刷新间隔；保存后可立即同步。采集只生成不可变快照。快照版本、采集时间、覆盖国家数、记录数和 SHA-256 哈希用于确定核对的是哪一批数据。

VATcomply 快照目前主要覆盖欧盟国家。若预期销售市场不在快照范围内，快照缺失只表示这个数据源没有提供数据，不能推断该地区税率为零，也不能把邻国税率拿来代替。

### 3. 检查地区覆盖 TAB

覆盖状态由当前读取的数据即时计算，不会另存一份可能过期的汇总：

- **已配置国家默认**：有一条启用的国家级规则；更具体的州 / 省和邮编规则仍可能覆盖它。
- **多条国家默认**：同一国家存在多条启用的国家默认规则。Checkout 按优先级和记录 ID 选中一条；应清理重复规则，避免配置含义不清。
- **部分地区已配置**：只有州 / 省或邮编规则，未匹配这些细分地址的交易会被阻止。
- **未配置 / 仅有停用规则**：没有能匹配该国默认地址的启用规则，相关交易无法通过税率检查。
- **快照未覆盖**：当前快照没有该国数据。这与 Checkout 规则是否存在是两件独立的事。
- **数值一致**：Checkout 国家默认税率与快照标准税率数值相同，仅是差异检查结果，不代表商品类别、纳税义务或生效日期已经核实。

规则数据或快照请求失败时，页面显示读取错误，不会把加载失败当成“未配置”。点击“查看结算规则”可进入当前 Checkout 规则列表。

### 4. 维护 Checkout 规则

只有根据适用于商家的税务资料核实后，才在“结算规则”中建立或修改税率。国家默认规则、州 / 省默认规则和邮编规则会立即影响新报价；已有订单保留下单时的金额快照。显式 0% 是合法规则，但必须是有依据的税务决定，不能用它填补未知区域。

当前找不到匹配规则时，报价和下单返回 `tax_rate_unavailable`，不会静默按 0% 收税。

## 快照为什么仍有用途

快照不应直接决定应收税额，但它可以提供**可复核的输入和差异信号**：保留供应方原始记录、检查数据是否变化、发现已有结算规则与外部标准税率不一致，并帮助管理员定位尚未核对的地区。只有在明确数据范围、税务适用性及责任人后，才有理由把经过核实的税率用于收费。

若需要覆盖多国、多商品类别、地方税、免税和税期规则，应接入提供交易级税务计算能力的服务，或先建立经税务责任人确认的税务资料库。单纯把另一个 API 的返回值复制进 `tax_rates`，不会让规则因此变得正确。

## 后续结构方向

在引入自动发布前，先补齐结算所需的税务语义：商品税务类别、地区辖区层级、税率类型和生效区间；规则记录来源、来源版本 / 哈希、核验状态和核验依据；然后让快照生成可审阅的候选版本，经显式审核后整体发布给 Checkout。Checkout 只读取当前有效的已发布版本，未覆盖或版本过期时继续阻止交易。

来源适配器、快照存储、税务政策和物流模板应保持独立。来源可以被替换或增加，不能让 VATcomply 字段成为 Checkout 或承运商数据结构的前提。
