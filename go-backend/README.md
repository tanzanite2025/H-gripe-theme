# Go Backend

This is the Go API service for the commerce platform. It serves both the Nuxt storefront and the Vue admin console.

The project is still under active development and has not launched in production. Treat this file as a practical backend entry point, not a production-readiness claim.

The independent local computer backup service is in `cmd/local-backup-maintenance`.
Use `local-backup-maintenance -config <absolute-private-configuration-path> -check-configuration-only` to validate local configuration and print a credential-free JSON report before initializing the executor. This does not connect to PostgreSQL, recover tasks or start HTTP; target environment acceptance remains incomplete.
Release integration is opt-in through `LOCAL_BACKUP_MAINTENANCE_ENABLED=true` in the controlled production env file. It preserves the backup overlay and checks existing maintenance gates before service updates; ordinary releases do not start or restart the maintenance executor. The image workflow includes its separate scanned Docker target; actual publication and target deployment remain unverified.
The release verifier shares Redis/backup overlay selection with deployment. Set `CHECK_RUNTIME_METADATA=true CHECK_CONNECTIVITY=false` when running `deployment/verify-vps-release-boundary.sh` to collect allowlisted container/network evidence without starting probe containers. Use a fresh `REPORT_DIR`; the metadata report always leaves target environment acceptance incomplete. `CHECK_CONNECTIVITY=true` separately enables the existing active probes.

## Local Development

From the repository root, start PostgreSQL and Redis:

```powershell
docker compose up -d postgres redis
```

Then run the backend:

```powershell
cd go-backend
Copy-Item .env.example .env -ErrorAction SilentlyContinue
Copy-Item config/config.example.yaml config/config.yaml -ErrorAction SilentlyContinue
go run ./cmd/server
```

Default local address:

- `http://localhost:9200`
- health check: `http://localhost:9200/health`

## Testing

```powershell
cd go-backend
go test ./...
```

## Backend Boundaries

- Handlers should parse requests, call services, and return responses.
- Business rules belong in `internal/service`.
- Persistence details belong in `internal/repository`.
- Database transactions should be owned by a clear service-level use case or a dedicated transaction helper.
- Payment and refund state should only change through verified provider callbacks or controlled admin/service flows.
- New code should not add WordPress compatibility paths unless they are explicit migration tools.
