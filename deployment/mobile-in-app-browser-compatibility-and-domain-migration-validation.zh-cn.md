# 手机应用内浏览器兼容与域名迁移回溯验证

验证日期：2026-11-12。本文记录代码与本地验证结果，不代表已部署到生产或已完成手机真机验收。

## 请求链路与处理边界

统一沿用「CDN/WAF → Caddy → Nginx → Nuxt/API」。公开 HTTP 协议升级由网关负责，Nuxt 不另设依赖转发头的 HTTPS 跳转中间件，避免本地开发、内部探针和代理链路受到重复跳转影响。

生成配置从 `ops_domain_bindings` 获取域名。GET/HEAD 用 301 升级 HTTPS，其他方法用 308，保留方法与请求体。前端只有一个提示组件，从浏览器当前位置生成链接，不写死当前域名；用户代理仅用于显示帮助，不决定页面能否访问，也不作为安全白名单。

## 回溯修复

- 链接跟随 SPA 路由、锚点、前进/后退和页面恢复更新，复制时再次读取当前位置。
- 现代剪贴板失败后尝试兼容复制；两个接口均失败时明确提示手动选择链接，只有复制成功才显示成功状态。
- 复制中的旧请求不会将新页面误标为“已复制”，临时复制节点会清理。
- 删除无法保证跳出应用的“打开浏览器”按钮，改为说明通过应用菜单打开。
- 会话存储不可用时仍能关闭提示。接入现有弹层状态，菜单及结账等弹层打开期间收起提示。
- 提示移到页头下方，避免与底部 Cookie 横条、操作栏叠在一起；支持窄屏、横屏和从右到左布局。
- 只填写新域名的重定向目标保留原路径和查询参数；明确指定页面、查询或片段的目标按原目标跳转。Caddy 生成和 Nginx 预览共享该规则。
- GitHub Actions 发布前端镜像要求 `STOREFRONT_SITE_URL` 是主站 HTTPS 源站；普通发布会读取线上首页 canonical 并与该变量比对，缺失、漂移或线上无法校验时阻断发布。计划换域名时，在 GitHub Actions 手动运行 `Publish Production Images`，将 `storefront_site_url` 填成新 HTTPS 源站；工作流用该值构建镜像，所有镜像成功发布后自动更新仓库 Actions variable。此迁移入口只跳过“新域名必须已在线”的比对，仍执行发布验证，也不会替代 Ops、部署环境、DNS/CDN 和证书更新。完成新域名部署后，普通发布会要求线上 canonical 与该变量一致。图片白名单自动包含 canonical 主机，不再静默使用旧域名默认值。
- 新增文案覆盖现有 20 种语言，源文件和聚合文件保持一致。

## 线上观察与未覆盖范围

本轮从当前执行环境发出只读请求：直连源站 Caddy 时，微信 Android、Facebook 内置浏览器、WhatsApp 的 HTTP 请求都返回 `308 Permanent Redirect`，Location 指向 HTTPS；公开域名前也同样返回 308，`Server: cloudflare`，而直连源站标记 `Server: Caddy`，证明 Cloudflare 正在转发该源站响应。各 UA 通过 HTTPS 均能读取页面。这个 HTTP 跳转足以作为截图里 `ERR_HTTP_RESPONSE_CODE_FAILURE` 的可信嫌疑点，但没有真实的出错手机和网络记录，仍不能说已证明因果。

页面脚本只能在 HTML 成功加载后运行。DNS/TLS 失败、CDN 挑战、应用自身拦截、地区网络或设备 VPN 影响，必须结合对应时间的 CDN 安全事件、Ray ID 和真机结果排查。不要按可伪造 UA 全面放行，也不要用前端提示替代入口可达性检查。有些应用提供普通 Safari/Chrome UA，无法可靠识别；提示不是访问门槛。

本次没有发布生产配置、修改 Cloudflare 或完成 iOS/Android 微信、Facebook、WhatsApp 的真机登录与支付验收。新生成的 Caddy 配置和部署前置检查会将 GET/HEAD 改为 301；正式部署后必须从源站和公开 CDN 各验证一次，确认响应已变为 301，再用报错手机实际点击复测。部署和域名切换时仍须同步域名绑定、DNS/CDN、证书、公开 URL、GitHub Actions 的 `STOREFRONT_SITE_URL`、支付/OAuth 回调域名及服务商域名校验；保留旧域名 DNS/TLS。详细规则与 Caddy 验证命令见 [EDGE_SECURITY_RUNBOOK.md](EDGE_SECURITY_RUNBOOK.md)。
